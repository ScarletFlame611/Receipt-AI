# Receipt-AI

Веб-сервис распознавания чеков. Система сначала находит чек на фотографии, потом распознаёт на нём текст движком Surya, извлекает поля и товарные позиции (моделями Donut и NER) и относит траты к категориям. Есть аналитика расходов и личный кабинет.

Бэкенд написан на FastAPI и включает ML-пайплайн на PyTorch (работает на CPU). Фронтенд это React-приложение на Vite. База данных PostgreSQL в продакшене или SQLite при локальной разработке.

С проектом можно работать тремя способами: поднять весь стек через Docker, запустить бэкенд и фронтенд локально по отдельности или открыть ноутбуки обучения в Google Colab. Ниже описан каждый из них.

## Структура проекта

```
src/            код бэкенда и ML-пайплайна (api, models, data, utils)
configs/        конфиги моделей и приложения (yaml)
alembic/        миграции БД
scripts/        вспомогательные скрипты (админ, сиды, докачка весов)
frontend/       React-приложение (Vite)
notebooks/      ноутбуки обучения и анализа (Colab)
weights/        веса моделей, не в git, докачиваются с Google Drive
data/           датасеты и загрузки, не в git
```

## Запуск через Docker

Одна команда поднимает весь стек сразу: базу PostgreSQL, бэкенд на FastAPI и фронтенд на React за nginx.

Из требований нужны только Docker и Docker Compose. Веса моделей готовить заранее не надо: при первом старте бэкенд сам скачивает их с публичного Google Drive в папку `weights`. Это включено по умолчанию (переменная `FETCH_WEIGHTS=1`); если веса уже лежат локально и качать их не нужно, поставьте `FETCH_WEIGHTS=0`.

Запуск:

```bash
cp .env.example .env
docker compose up --build
```

После сборки приложение открывается по адресу http://localhost:8080 (это фронтенд вместе с проксируемым API), а Swagger бэкенда напрямую по адресу http://localhost:8000/docs.

Первый запуск идёт дольше обычного: бэкенд скачивает веса (около гигабайта) и базовые модели Surya и HuggingFace, после чего прогревает пайплайн. Пока он не готов, проверка `/api/health` отвечает кодом 503, и именно по ней Docker понимает, что сервис готов. Кэш моделей и веса сохраняются между запусками, поэтому повторный старт быстрый.

Чтобы при первом старте автоматически создался администратор, задайте в файле `.env` перед запуском переменные `ADMIN_EMAIL` и `ADMIN_PASSWORD`. То же самое можно сделать вручную в уже работающем контейнере:

```bash
docker compose exec backend python scripts/create_admin.py --email admin@receipt-ai.local --password Secret123
```

Несколько полезных команд при работе со стеком:

```bash
docker compose logs -f backend
docker compose exec backend alembic upgrade head
docker compose down
docker compose down -v
```

Первая показывает логи бэкенда (в них виден прогрев моделей), вторая накатывает миграции вручную, третья останавливает стек, а последняя ещё и удаляет тома вместе с базой и кэшем.

Стек состоит из трёх сервисов. База PostgreSQL 16 работает внутри сети и наружу порт не выставляет. Бэкенд (FastAPI с uvicorn и ML-пайплайном) слушает порт 8000. Фронтенд (собранный React, который nginx раздаёт и заодно проксирует к нему API) доступен на порту 8080. Данные базы и кэш моделей хранятся в томах Docker, а папки `weights` и `data` монтируются с хоста.

Пара деталей по сборке образа: torch ставится из CPU-индекса PyTorch, без CUDA, а surya-ocr ставится с ключом `--no-deps`, потому что её зависимости конфликтуют с пинами проекта (подробнее в Dockerfile).

## Локальный запуск (для разработки)

Бэкенд и фронтенд запускаются по отдельности. По умолчанию используется SQLite, так что отдельная база не нужна.

### Бэкенд

Понадобится Python 3.11. Сначала создаём виртуальное окружение и ставим зависимости. Порядок установки важен: сперва torch из CPU-индекса, затем surya без зависимостей, и только потом всё остальное (torch и surya к этому моменту уже стоят, и pip их пропустит).

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux или Mac: source .venv/bin/activate

pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu
pip install --no-deps surya-ocr==0.13.1
pip install -r requirements.txt
```

Дальше готовим окружение и запускаем сервер:

```bash
cp .env.example .env
python scripts/fetch_weights.py
alembic upgrade head
python scripts/create_admin.py --email admin@receipt-ai.local --password Secret123
uvicorn src.api.main:app --reload --port 8000
```

Здесь `fetch_weights.py` скачивает веса моделей с Google Drive, `alembic upgrade head` создаёт схему базы, а создание администратора делается по желанию. После запуска API доступен на http://localhost:8000, Swagger на http://localhost:8000/docs, а проверка готовности на http://localhost:8000/api/health (она отвечает 200 только когда модели прогреты).

### Фронтенд

Понадобится Node.js версии 18 или новее.

```bash
cd frontend
npm install
npm run dev
```

Dev-сервер поднимается на http://localhost:5173 и проксирует запросы к API на http://localhost:8000 (настройка в `vite.config.js`), поэтому бэкенд в это время должен быть запущен. Адрес бэкенда при необходимости меняется переменной `VITE_API_TARGET`.

## Ноутбуки в Google Colab

В папке `notebooks/` лежат ноутбуки с обучением моделей и анализом данных. Каждый из них рассчитан на запуск в Google Colab по кнопке «Run all», без каких-либо ручных действий. Служебная ячейка в начале сама клонирует репозиторий с GitHub, доустанавливает библиотеки и подтягивает данные и готовые веса с публичного Google Drive (через утилиту `gdown`), а базовые модели берёт с HuggingFace Hub. Поэтому скачивать что-либо руками не нужно.

Чтобы запустить ноутбук, откройте его в Colab (для обучающих лучше выбрать среду с GPU) и нажмите «Runtime», затем «Run all».

В обучающих ноутбуках есть переключатель `SKIP_TRAINING` в ячейке настройки. Когда он равен `True` (так задано по умолчанию), обучение пропускается и вместо него скачиваются готовые веса, это быстрый способ прогнать ноутбук целиком и увидеть метрики. Если поставить `False`, модель обучается с нуля, и тогда нужен GPU, а времени уходит заметно больше.

Сами ноутбуки:

- `00_explore_data`, разведочный анализ датасетов CORD и SROIE;
- `01_baseline_donut`, baseline готового Donut до дообучения;
- `02_train_detector`, обучение детектора чека на YOLOv8;
- `03_train_donut`, дообучение Donut на реквизиты по SROIE и проверка переноса на CORD и русский чек;
- `04_train_categorizer`, категоризатор трат на синтетике как baseline;
- `05_explore_ofd`, анализ датасета ОФД для NER товаров и брендов;
- `06_prepare_ner_data`, подготовка BIO-разметки для NER;
- `07_train_ner`, дообучение NER на xlm-roberta для товаров и брендов;
- `08_explore_dremov`, анализ датасета Дрёмова и сборка реального датасета категоризатора;
- `09_train_categorizer_real`, категоризатор на реальных данных и сравнение синтетики с реальностью.

## Веса и данные

Веса моделей и датасеты в репозитории не хранятся из-за размера, их источник это публичный Google Drive. В Docker они скачиваются автоматически при старте, локально командой `python scripts/fetch_weights.py`, а в ноутбуках той же служебной ячейкой. Пути к весам и параметры моделей заданы в конфигах `configs/*.yaml`.
